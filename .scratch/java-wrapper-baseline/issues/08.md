## What to build

Preview and record a purchase that explicitly creates a required security while preserving existing definitions and avoiding ambiguous reuse.

## Acceptance criteria

- [ ] Require explicit creation, security name and currency; allow optional external identifiers and use available identifiers for unambiguous reuse rather than silently creating duplicates.
- [ ] Show security creation/reuse and linked accounts in preview; reject ambiguous matches or missing required definitions without applying financial changes.
- [ ] Use the shared decimal, time, update, preview, atomic-write, and backup contracts. Saved new definitions and linked entries reload correctly with pinned core.
- [ ] Verify creation without external identifiers, reuse, ambiguity, failed creation, and unrelated-definition preservation through the launcher and candidate validation.
