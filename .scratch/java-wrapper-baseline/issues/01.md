## What to build

Build a local Docker image that can load, inspect, save, and reload an anonymized portfolio and convert and extract a representative PDF without launching the desktop application.

## Acceptance criteria

- [ ] Pin an upstream source revision and local image identity; record reproducible build/JDK dependencies, Linux architecture, licensing, attribution, and actual commands/results.
- [ ] Exercise upstream persistence, financial models, linked purchase/sale entries, and PDF-to-text/extraction headlessly through a real container entry point without a display. Do not substitute a Python financial model or serializer.
- [ ] Establish independently specified, anonymized, versioned XML and PDF/text fixtures covering multiple account pairs, purchase/partial/full sale, dividends, fees/taxes, FX, security references, settings, and classifications. Reference samples require anonymization review; never use the real portfolio.
- [ ] Compare no-op round trips and intended financial changes semantically after loading with pinned core; successful loading alone is insufficient.
- [ ] Declare only passing release/revision/ID-reference-model/image combinations in an initial support matrix, separating input/output representations and versions. Reject untested representations and migrations; report feasibility blockers explicitly rather than claiming support.
