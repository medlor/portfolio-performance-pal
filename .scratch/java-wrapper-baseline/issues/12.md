## What to build

Allow a financial command to apply a fixture-validated upstream model migration while clearly disclosing the output version and protecting the exact original state.

## Acceptance criteria

- [ ] Declare passing input/output model and representation combinations and migration paths for exact revision/image entries, with independently specified pre/post semantic expectations.
- [ ] Disclose migration and output model version in preview; owner manages desktop compatibility independently without a configured desktop-release write gate.
- [ ] Before every persisted migration create a separate non-overwriting backup of the exact operation input even if a daily backup exists; required backup failure prevents replacement, and retain migration backups for two years.
- [ ] Queries/previews may migrate in memory but never persist it. --update validates disposable copies without modifying the selected portfolio; reject unsupported migrations before mutation.
- [ ] Verify intended financial changes plus unrelated-data preservation, exact migration backups, existing daily protection, stale input, failures and read/update immutability through container tests and candidate gates; document validated paths only.
