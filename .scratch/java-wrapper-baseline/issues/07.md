## What to build

Record a validated purchase with --apply, preserving unrelated data and protected recovery state while refusing stale or unsafe writes.

## Acceptance criteria

- [ ] --apply computes a fresh plan with the invocation snapshot and fixed validated engine; it requires no additional interactive prompt or persisted prior-preview approval.
- [ ] Require Portfolio Performance closed; implement/document writer coordination without claiming the GUI participates. Serialize on the same filesystem, inspect saved semantics with pinned core, recheck changed input immediately before atomic replacement, and preserve original bytes on rejection/pre-replacement failure.
- [ ] Before the first successful Europe/Berlin daily change create <filename>.YYYY-MM-DD.bak unless it exists; never overwrite it, and required backup failure prevents replacement.
- [ ] Only after a successful financial write prune tool-owned daily backups, retaining the three most recent dates per month for the current and preceding 23 months, or all when fewer; remove older owned dates. Preserve separate two-year additional-backup policies.
- [ ] Report post-replacement pruning failures as successful financial changes with recovery information rather than inviting repeat application; previews, failed operations, and skipped duplicates never prune.
- [ ] Exercise real Linux permissions/mounts, stale/concurrent inputs, semantic preservation, backup failures/existing backups, calendar boundaries/retention, and failures before/after replacement through command/container tests; extend updater gates.
