## What to build

Protect the selected portfolio with due monthly backups at launch and exact pre-upgrade backups before actual upgrade attempts.

## Acceptance criteria

- [ ] Choose distinct collision-safe backup names and tool-ownership markers; never overwrite existing required backups or prune unowned files.
- [ ] Create a monthly backup when due on launch using Europe/Berlin calendar boundaries. After inactivity, capture current state once rather than fabricating missed monthly states; use no background timer.
- [ ] Expose the pre-upgrade backup operation for every actual attempt; unchanged-release checks create no additional update backup. Required backup failure stops the protected operation.
- [ ] Retain monthly/update backups for two years separately from daily and migration backups; any pruning happens only following successful financial writes.
- [ ] Verify selected-file/configuration paths, ownership, backup failures, collisions, and calendar boundaries through public launch/update behavior with temporary portfolios.
