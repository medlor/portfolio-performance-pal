## What to build

Import supported foreign-currency and mixed purchase/sale/dividend documents as one validated financial decision using stated exchange information.

## Acceptance criteria

- [ ] Establish anonymized representative foreign-currency and mixed-document PDF/text fixtures rather than inferring support from domestic purchase/sale samples. Verify actual PDF conversion, extraction, currencies and rate semantics.
- [ ] Keep statement booked amounts authoritative; allow required exchange supplementation only when missing, disclose supplements/derivations, and reject conflicting values without live rate lookup.
- [ ] Validate every recognized member together, including full affected quantity histories and stable timestamp ordering. Unsupported, ambiguous, incomplete, contradictory, invalid or unresolved duplicate-uncertain content prevents the whole financial import.
- [ ] Verify each transaction type, FX fees/taxes and links with pinned core; test invalid later members, repeat imports, document-wide overrides, and post-replacement metadata failures via the real launcher/container.
- [ ] Complete maintenance/support documentation with exact tested revisions/images/models/migrations/layouts, reproducible commands and limitations. The updater must exercise all implemented command, PDF, semantic, backup, recovery and migration gates without changing independent expectations; retain prior supported combinations/layouts as regressions.
