## What to build

Use --update to discover, build, validate, and automatically activate a released wrapper/upstream pair while preserving the selected portfolio and previous validated pair on failure.

## Acceptance criteria

- [ ] Resolve latest stable official upstream and released wrapper tags to immutable revisions; define/document initial release/bootstrap packaging and cache keys. Use isolated checkouts without changing the owner repository, generating adapter fixes, or publishing images.
- [ ] Coordinate updates with a lock; perform due monthly and required actual-attempt backups. An unchanged validated pair reuses its image; failed discovery/build/checks stop the requested operation instead of silently continuing on the older pair.
- [ ] Keep financial files out of build contexts and uploads. Run fixed independent fixture and real container checks, then validate a disposable local copy of the selected portfolio, including --file. Compare financial/unrelated semantics and allowed migrations without replacing the original or altering import metadata.
- [ ] Produce a report/manifest with wrapper and upstream revisions, image identity, support/migration/layout evidence, dependencies, and executed checks; compilation or candidate-only reload is not sufficient evidence.
- [ ] Atomically select launcher implementation and image together, retain the previous pair after any pre-activation failure/interruption, and fix the selected engine revision for each processing invocation.
- [ ] --update activates passing candidates without --apply and never writes the selected portfolio. Wire automatic checks before every preview/import as those commands are introduced; each subsequent feature extends fixed candidate validation before declaring its support.
