## What to build

Apply all recognized purchases in one PDF together while skipping confirmed re-imports and requiring a document-wide override for every suspected duplicate.

## Acceptance criteria

- [ ] Keep document hashes, broker references and associated transaction IDs in adjacent metadata, never custom XML fields or user-visible notes. Confirm identity against the current portfolio before skipping; overrides never authorize adding confirmed re-imports.
- [ ] List every suspected duplicate in preview; --apply alone is insufficient and an explicit document-wide override bypasses duplicate uncertainty only, never financial validation.
- [ ] Missing metadata, stale IDs, inconsistent evidence, external edits or restored backups fall back to suspected-duplicate checks instead of assuming a new import.
- [ ] Validate and apply the complete document through shared financial/update/migration/safe-write rules with no partial financial import. Reject changed portfolio or PDF inputs used for planning.
- [ ] Define/document recovery across separate portfolio/metadata writes so incomplete bookkeeping cannot authorize repeat imports. Report financial success after replacement despite metadata/pruning failure with recovery guidance that does not invite repeating the import.
- [ ] Verify new/repeated documents, broker-reference identity, similarity, overrides, uncertain evidence, interrupted metadata, restored backups, multi-purchase atomicity and failure injection through real commands; extend updater gates.
