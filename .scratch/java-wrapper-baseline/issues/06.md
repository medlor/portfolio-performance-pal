## What to build

Preview a same-currency purchase of an existing security using resolved accounts and upstream financial models without recording financial changes.

## Acceptance criteria

- [ ] Run the mandatory update workflow before planning, then hold its engine revision fixed; stop preview on update failure.
- [ ] Resolve an unambiguous existing security using supplied identifiers and required securities-account/cash-account selections; reject missing or ambiguous matches.
- [ ] Accept quantity and price, gross value, or booked total with fees/taxes as appropriate. Derive only determined missing values using decimal arithmetic and tested upstream scaling/rounding; reject contradictions and unrepresentable precision.
- [ ] Construct consistent linked proposed entries through upstream models; show choices, supplied/derived amounts, dates, and explicit times, using 11:00:00 only when the purchase time is missing.
- [ ] Preview changes neither portfolio nor import metadata and creates/prunes no daily or migration backups. Clearly distinguish permitted launch/update backups.
- [ ] Verify preview, rejection, decimal boundaries, path/account precedence, explicit/fallback times, and fixed-revision behavior through the launcher; add these cases to candidate compatibility validation.
