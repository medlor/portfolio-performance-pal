# Automatic upstream updates: research notes

Researched 2026-10-06. This note separates verified upstream facts from a proposed wrapper design. No upstream build, headless runtime, or migration was executed; no private portfolio contents were inspected.

## Verified upstream facts

- The official GitHub release endpoint currently returns stable, non-draft `0.88.0`, published 2026-10-04. Assets include Linux x86_64/aarch64 application archives, SHA-256 digests, and detached signatures, plus other desktop platforms; the release page also provides source archives. The listed assets do not include a standalone core library. [Release](https://github.com/portfolio-performance/portfolio/releases/tag/0.88.0), [release API](https://api.github.com/repos/portfolio-performance/portfolio/releases/latest).
- Release `target_commitish` is `master`, so it does not identify immutable release source. Tag `0.88.0` resolves first to annotated tag object `d876ebcef1aa97bf84436ba55daa1f958599f3b8`, then commit `8de1fe41d71a2c1b74a6bfbe913f885899aaf123`. Resolve and record the commit before fetching/building. [Tag ref](https://api.github.com/repos/portfolio-performance/portfolio/git/ref/tags/0.88.0), [tag object](https://api.github.com/repos/portfolio-performance/portfolio/git/tags/d876ebcef1aa97bf84436ba55daa1f958599f3b8).
- The core module uses `eclipse-plugin` packaging. Its release manifest requires Java 21, Eclipse core runtime, HTTP libraries, service components, and matching PDFBox1/PDFBox3 bundles; imports include SWT, Equinox security, XStream, protobuf and others. A core JAR alone is insufficient dependency closure. [Core POM](https://github.com/portfolio-performance/portfolio/blob/0.88.0/name.abuchen.portfolio/pom.xml), [release manifest](https://github.com/portfolio-performance/portfolio/blob/0.88.0/name.abuchen.portfolio/META-INF/MANIFEST.MF).
- Release build configuration uses Tycho 5.0.4, a target platform, and JavaSE-21. Its reactor separates target definition, PDFBox bundles, core, core tests, UI and product. Signing/installer steps default to skipped; `local-dev` also skips checks and protobuf generation, so it needs explicit evaluation before use in validation. [Release parent POM](https://github.com/portfolio-performance/portfolio/blob/0.88.0/portfolio-app/pom.xml).
- Upstream documents selective core compilation and verification including target definition, PDFBox1, PDFBox3, core, JUnit helpers and core tests. This supports a source-build route without desktop packaging as an intended workflow. The documented offline test flag requires dependencies already cached. [Build instructions](https://github.com/portfolio-performance/portfolio/blob/master/CONTRIBUTING.md#with-maven).
- Persistence source upgrades the model during XML loading and rejects newer file versions; saving depends on Eclipse `Platform` and writes through an output stream to the supplied file. Load-time migration can therefore exist in memory during preview without changing the original, provided the wrapper does not save it. These observations are from inspected `master`, not a guarantee for every release. [ClientFactory](https://github.com/portfolio-performance/portfolio/blob/master/name.abuchen.portfolio/src/name/abuchen/portfolio/model/ClientFactory.java).

## Selected automation design

Before each preview/import, query stable Portfolio Performance and released wrapper metadata. Resolve their tags to immutable commits and compare them with the active validated pair. An unchanged check creates no upgrade backup. A failed check stops the command, retaining the active pair.

For a changed pair, first create the requested pre-upgrade backup. Fetch immutable source into isolated checkouts without modifying the owner's repository; run a selective Tycho core/test build and compile the released wrapper adapter against that candidate. Cache Maven/Tycho downloads locally to reduce repeat work, but key candidate outputs by upstream commit, wrapper revision, architecture and dependency/build configuration. Build a local candidate image and never publish it. Fixed independent wrapper fixtures must pass in addition to upstream tests; tests and adapter code must not be automatically rewritten to accommodate failures.

Validate load/save/reload, supported old-file migration paths, transaction preservation, security/account identity, taxes/fees/currencies, PDF extraction and import actions. Exercise the actual container entry point without a display. Then inspect a local disposable copy of the selected portfolio without uploading it; passing fixtures alone cannot establish compatibility with every real file. Atomically activate the released wrapper implementation and candidate image together only after all gates pass. `--update` activates automatically, while `--apply` is reserved for financial changes. Failures stop preview/import and leave the previous validated pair available.

On launch, make the monthly backup if due, without a timer; retain backups for two years. Immediately before committing a tested migration with transaction changes, separately preserve exact original bytes and disclose the migration in preview. Updating an image does not save/migrate a portfolio. Desktop upgrades remain the owner's responsibility.

## Alternatives and remaining limits

Official desktop archives are a plausible source of already assembled runtime bundles, avoiding rebuilding upstream; however, archive contents and the required subset were not inspected here. Their desktop packaging establishes neither a supported headless API nor successful plain-classpath execution. Plain classpath and a minimal headless Equinox application are alternative runtime experiments; neither is proven. Source build is the better documented initial route and enables upstream tests, while official release bundles could later supply a validated runtime closure.

Automatic discovery/build/test/promotion is feasible as a design; automatic compatibility is not promised. Expected human fixes include Java/API signature changes, changed extractors/import actions, OSGi services/resources, native/SWT dependencies, JDK/Tycho/target-platform changes, and previously untested file migrations. A release failure must not silently fall back to importing with an older version. Backups and retained images do not prove that an older image can reopen a portfolio after a newer save.
